# 最终需求基准与当前验收范围

需求来源：用户上传《BOSS直聘 AI 自动求职助手需求说明(1).docx》，全部 55 章及末尾原则。原文件 SHA-256：`0d246e0182a55e247b1a635ba860cbb1533003411d385ad79a79ed0b8dbf18be`。原文件和个人资料不放进代码仓库。

以下是对基准的逐项追踪，不修改、不降低原需求。**0.1.0 是可安装的工程验证版本，不是完整自动求职成品。** “已实现”表示有对应实现；设备、真实 API 与真实 BOSS 的验证状态以 TEST_REPORT 为准。

| 章 | 要求 | 当前实现及尚缺部分 |
| --- | --- | --- |
| 1 | BOSS 优先 | 只做 BOSS；没有分散到其他平台 |
| 2 | Android 主版本 | 原生 APK、Java 源码、构建配置；真实手机兼容性待验收 |
| 3 | 中文五类页面 | 首页、岗位、HR、简历、资料；记录统计已有；统计并非平台全量数据 |
| 4 | DeepSeek / OpenAI Compatible | HTTPS 地址、模型、温度可配置；真实 Key 调用需用户在手机内测试 |
| 5 | Key 仅内存 | 进程内存、退出清除、后台30分钟失效、不保存输入状态；有核心/设备测试 |
| 6 | 临时或记住 BOSS 登录 | 未实现助手托管会话；改走官方 APP 登录，临时使用后需在 BOSS 手动退出 |
| 7 | 自动搜索 | 搜索字段和 BOSS 控件驱动已实现；控件绑定及平台实际搜索结果待手机联调 |
| 8 | AI 岗位匹配 | 0–100 分、原因、缺口、风险、候选阈值；返回结构检查与本地先筛选 |
| 9 | 不编造资料 | 答复只能使用用户授权的原始事实；模型选择证据，未知转待本人 |
| 10 | 个性化招呼 | 生成含岗位名及真实资料摘录的草稿；BOSS 首次招呼仍可能是官方默认内容 |
| 11 | 三种模式 | 默认测试不发；半自动确认；自动策略有代码，但整个真实闭环未验收 |
| 12 | 重复投递保护 | ID 优先、联合指纹后备、去重窗口；UNKNOWN 必须人工核对 |
| 13 | 每日投递上限 | 发送前占额度，结果不确定也计入；达到上限暂停 |
| 14 | 操作频率 | 统一操作间隔，最低5秒；没有反检测或伪装模块 |
| 15 | 验证码 | 可见安全提示触发暂停和提醒；真实验证码页面识别仍需验收 |
| 16 | HR 自动回复 | 当前可见会话读取、生成、受控发送；通知只提醒，不当作完整聊天 |
| 17 | 自然拖延 | 多个简短模板，不暴露“AI不知道” |
| 18 | 消息分类 | 规则分类与 AI 证据选择；分类持久记录；复杂问题转本人 |
| 19 | 完整上下文 | 包含已确认资料、简历、偏好、岗位和记录历史；不可见历史需补充核对 |
| 20 | 学习本人答案 | 本人勾选授权、发送确认后保存为 FAQ |
| 21 | FAQ 管理 | 新增、修改、删除、按类别使用 |
| 22 | 重要消息提醒 | 面试、薪资、到岗、合同等通用通知，详情在安全页面看 |
| 23 | 敏感资料保护 | 高敏感请求仅拖延及提醒，不能自动发证件/验证码/密码 |
| 24 | 自动发送简历 | 未完成；当前附件要在 BOSS 官方 APP 手动选择和发送 |
| 25 | 消息去重 | 持久任务 ID，先记 UNKNOWN 后发送；相同问题采用保守去重，不自动重试 |
| 26 | 投递记录 | 岗位、评分、草稿、状态已记录；已读/面试/Offer 等平台状态同步未完成 |
| 27 | 回复审计 | 原问题、分类、草稿、实际内容、修改/自动标记及时间 |
| 28 | Android 通知 | 运行通知和通用提醒；不包含 HR 原文、Key、证件号 |
| 29 | 后台运行 | 用户启动的前台服务；锁屏/页面不可见不点击，不能承诺锁屏继续操作 |
| 30 | 最小权限 | 网络、前台服务、通知、可选无障碍/通知读取；文件用系统选择器 |
| 31 | 可靠 UI 识别 | 使用控件 ID 和祖先约束，唯一匹配检查，无固定坐标；版本适配待验收 |
| 32 | BOSS 独立 | BossService/BossTree/BossNotifications 与 AI、存储、规则分开 |
| 33 | 异常恢复 | 账本恢复但不自动恢复发送；不确定结果人工核对；Key 不恢复 |
| 34 | 网络异常 | HTTP错误/超时/无效JSON处理；BOSS失败暂停，未完成完善的页面加载重试 |
| 35 | AI 费用 | 调用次数上限、token和费用估计；单价需用户核对，估计不等于账单 |
| 36 | 本地数据 | Keystore + AES-GCM 私有存储，无开发者云服务 |
| 37 | 备份 | 加密导入导出资料/偏好/FAQ，排除Key/会话/聊天/简历文件 |
| 38 | 隐私清除 | 选择性与全部清除；BOSS 登录需到官方 APP 退出 |
| 39 | 日志安全 | 无请求头/响应体日志，通用错误；没有完整用户日志浏览器 |
| 40 | GitHub 安全 | 仅代码与合成测试，忽略隐私文件；提交前扫描 |
| 41 | Actions | 自动测试、lint、构建预览 APK，无需真实 API Key |
| 42 | 安装即用 | APK 本身无需 Python/Node/ADB；BOSS自动化仍需权限、绑定及真机验收 |
| 43 | 版本与更新 | 显示0.1.0；源码链接；自动检查 Releases 尚未实现，不自动下载更新 |
| 44 | 先运行上游 | 已实跑首选服务/测试、备选前端；详见 UPSTREAM_REVIEW |
| 45 | 不机械复制 | 不复用持久Key、桌面登录缓存、私有Hook、虚构个人资料 |
| 46 | 分阶段开发 | 核心、Android、测试、构建已有；真实 BOSS 联调仍在后续阶段 |
| 47 | 实际测试 | 核心和模拟设备覆盖；真实 BOSS 掉线/改版/风控、实际手机后台尚未验收 |
| 48 | 12类HR问题 | 12 个参数化合成测试，覆盖直接回答/拖延/敏感提醒 |
| 49 | 回复风格 | 简短事实答复和短拖延模板；更细的语气改写尚未实现 |
| 50 | 防无限拖延 | 一次拖延后设 waiting；后续追问只提高本人处理提醒 |
| 51 | 人工接管 | 会话接管开关 + 检测本人输入时暂停，发送前再次检查 |
| 52 | 明确运行状态 | 顶部状态、全局立即停止和通知操作 |
| 53 | 尊重安全机制 | 风控/验证码/登录/界面异常均停止，不绕过 |
| 54 | 交付材料 | APK、源码、中文使用/构建/隐私/测试文档；以实际生成文件为准 |
| 55 | 完整理想闭环 | 尚未达到；主要缺真实 BOSS 版本适配、全量会话/历史、附件及投递确认 |

下一步需要用户手机上真实 BOSS 的版本、页面可访问性与官方登录后的测试模式核对结果。无需把 API Key、Cookie、Session 或私人简历交给开发者。
